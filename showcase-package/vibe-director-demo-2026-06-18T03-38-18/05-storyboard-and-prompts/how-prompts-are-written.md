# Prompt 是怎么写出来的

这个 demo 里的 prompt 不是手工随便拼的，而是从项目状态逐层编译出来的。

## 1. 先有镜头目标

项目先把故事整理成镜头：

- `shot_storyboard_1-1`：雨夜偶遇发光车票，6 秒。
- `shot_storyboard_1-2`：末班电车亮灯，4 秒。

当前真实提交的是第 1 段，避免一次测试烧太多视频。

## 2. Agent 选择参考模式

当前第 1 段选择的是：

`全能参考 / omni_reference`

原因是这个镜头比较简单，重点是角色、场景、道具和一个连续动作，不需要故事板快切。

## 3. 参考图按职责排序

发给视频模型的参考图顺序是：

1. `scene_reference`：街道环境，只控制地点、天气、光线、色温。
2. `character_reference`：戴耳机的女孩，只控制身份、发型、服装轮廓。
3. `prop_reference`：发光车票，只控制物体外观和交互尺度。

Prompt 里会明确禁止把参考图变成额外镜头、目录图、分屏或画中画。

## 4. 再写视频模型合同

Prompt 会写清楚：

- 总时长：6 秒。
- 可见剪辑数量：1 个连续镜头。
- 不要字幕、Logo、水印、UI、面板、prompt 痕迹。
- 不要 BGM，保留后续音效和对白空间。
- 风格是 1990 年代日本 TV 动画感，不要真人写实、3D CG 或游戏渲染。

完整文本见：

`seedance_prompt.md`

## 5. QA 再检查

提交前有两层检查：

- `director-rule-qa.json`：检查结构硬规则，比如参考图职责、可见剪辑数量、BGM 禁用等。
- `director-text-qa.json`：检查文本层面的冲突和歧义。

当前两项都通过。
